# Sync (`sync.mjs`) and synced tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `node scripts/sync.mjs` brings a spawned project's agentic layer up to a template release (dry-run by default, `--apply` to write), never losing a local edit silently, and the template's tests move to a synced `tests/agentic/` directory.

**Architecture:** Three trees (old template at `based_on`, new template at the target, the project) are compared per in-scope path with the spec's decision table. Template trees come from GitHub release tarballs (a minimal tar reader over `zlib.gunzipSync`) or from local directories (`--from`/`--base`). A pure planning module decides; the CLI loads trees, prints, checks git state and writes.

**Tech Stack:** Node 22 ESM (`.mjs`), `node:test`, `node:zlib`, `fetch`, `git` CLI, no dependencies. Style follows the existing scripts (double quotes, header comment with usage and exit codes).

**Spec:** `docs/superpowers/specs/2026-11-24-sync-design.md` (parent: `docs/superpowers/specs/2026-11-23-boilerplate-design.md`, milestone 7)

## Global Constraints

- Only paths owned by the **agentic** layer of `layers.json` are read or written; the only other file touched is `boilerplate.lock`, and only its `based_on`.
- Default is a dry-run that writes nothing; `--apply` writes. Release tags are `v<version>`.
- No dependencies beyond Node. No schedule, hook or workflow; `.claude/`, `.github/workflows/` and `_bmad/` are protected and not edited.
- Exit codes: 0 nothing to do (or applied cleanly), 1 changes pending in a dry-run or conflicts remain, 2 the run failed (network, bad lock, dirty paths, not a git repository).
- Files are compared as bytes; no line-ending normalisation. No merge of conflicting edits, no `.orig` files.
- GitHub token and API base come from the same sources as `staleness.mjs` (`GH_TOKEN`, `GITHUB_TOKEN`, `gh auth token`; `STALENESS_GITHUB_API` for tests). `staleness.mjs` is not changed, so its small fetch helper is repeated in `sync.mjs`.
- Plan completely before writing: an error never leaves a partly written project.
- Code, comments, commit messages and docs are in English. Keep the diff small. Work on a branch `feat/sync`; a human merges.

## Review Focus

- A tarball entry whose path has `..`, is absolute, or is a symlink must never be returned or written outside the project root.
- A dry-run (the default) must leave the project byte-identical, including `boilerplate.lock`.
- A dirty path that the plan would write blocks the run with exit 2 **before any** write; unrelated dirty files do not block.
- A failed fetch of either tarball (404, network) exits 2 and names the tag; nothing is written.
- A project file that differs from the old template only by CRLF line endings is a conflict and is not overwritten without `--force`.

### Task 3: The decision table (`sync-plan.mjs`)

**Files:**
- Create: `scripts/sync-plan.mjs`
- Modify: `scripts/commands.json` (add `"sync-plan"` to `notCommands`)
- Test: `tests/agentic/sync-plan.test.mjs`

**Interfaces:**
- Consumes: `owns(layer, path)` from `scripts/layers.mjs`; `Map<string, Buffer>` trees from `readTarball`.
- Produces: `export function planSync({ oldTree, newTree, oldLayers, newLayers, read }): Array<{ path: string, action: "add"|"update"|"delete", reason?: string }>`
  - `oldLayers`/`newLayers` are the `layers` objects of each tree's `layers.json` (only `.agentic` is used); a missing `agentic` layer means nothing is in scope for that tree.
  - `read(path): Buffer | null` returns project bytes (`null` when absent).
  - An item **with `reason`** is a conflict; `action` is what `--force` would do (`update` if the project file exists, `add` if it does not, `delete` for template-removed files). Items without `reason` are clean changes. Paths already current produce no item. Result is sorted by path.
  - Reasons: `"edited locally"`, `"deleted locally"`, `"exists locally but not in your base version"`, `"removed by the template, edited locally"`.

- [ ] **Step 1: Write the failing tests** in `tests/agentic/sync-plan.test.mjs`, one per table row, with small in-memory trees (`new Map`) and `read` over an object. Each asserts the exact returned array:
  - project equals new → `[]` (also when the project was spawned after `based_on`).
  - old equals new, project edited → `[]` (local edit stays, not reported).
  - old equals new, project deleted the file → `[]` (not resurrected).
  - in new, absent from project and old → `[{ path, action: "add" }]`.
  - project equals old, new differs → `[{ path, action: "update" }]`.
  - project differs from old, new differs from old → `[{ path, action: "update", reason: "edited locally" }]`.
  - project deleted a file old had and new changed → `[{ path, action: "add", reason: "deleted locally" }]`.
  - file exists in project, absent from old, differs from new → `[{ path, action: "update", reason: "exists locally but not in your base version" }]`.
  - only in old, project equals old → `[{ path, action: "delete" }]`.
  - only in old, project edited → `[{ path, action: "delete", reason: "removed by the template, edited locally" }]`.
  - only in old, absent from project → `[]`.
  - scope: a path in `new` owned by another layer or by none (`src/app.js`, `CLAUDE.md`, `scripts/release.mjs` via exclude, `template.json`) never appears; an old-only path is judged by `oldLayers`, a path in `new` by `newLayers` (a path only `oldLayers` owns, present in both trees, is ignored).
  - CRLF: project bytes equal to old with `\r\n` line endings while new differs → conflict `edited locally`.
  - files that exist only in the project are never in the result.
  - result is sorted by path.

### Task 4: `sync.mjs` dry-run: inputs, trees, report

**Files:**
- Create: `scripts/sync.mjs`
- Test: `tests/agentic/sync.test.mjs`

**Interfaces:**
- Consumes: `readTarball`, `planSync`, `loadLayers` (`scripts/layers.mjs`), fixtures from Task 2.
- Produces the CLI `node scripts/sync.mjs [--to <x.y.z>] [--apply] [--force] [--diff] [--from <dir>] [--base <dir>] [--root <dir>]` (default root: current directory). Internals are not exported. Behaviour fixed here:
  - Reads `<root>/boilerplate.lock` (`based_on`, `repo`); missing or unusable → exit 2, message names `scripts/init.mjs`.
  - Target: `--from <dir>` → version from `<dir>/template.json`; else `--to`; else latest release `${STALENESS_GITHUB_API ?? "https://api.github.com"}/repos/<repo>/releases/latest` (`tag_name` minus `v`).
  - New tree: `--from` directory walked (skipping `.git`, `node_modules`) or tarball `GET <api>/repos/<repo>/tarball/v<target>`. Old tree: `--base` directory or tarball for `v<based_on>`. Each tree's `layers.json` is read from the tree itself; a tree without one → exit 2.
  - Target equal to `based_on` → print `already at <version>`, exit 0. Target older → exit 2 (refused).
  - Dry-run prints the groups `add`, `update`, `delete`, `conflict` (with reason), only non-empty ones, then a summary line and `release notes: https://github.com/<repo>/releases/tag/v<target>`; paths repo-relative with `/`. Exit 1 when the plan has items **or** the target differs from `based_on` (the lock would move); exit 0 only for the no-op above.
  - `--diff`: after the groups, a unified diff (via `git diff --no-index` between temp copies, project vs template) for each update and conflict; a missing side is an empty file.
  - Fetch errors (404, network, rate limit) → exit 2 with a message naming the host/tag; no output of a partial plan.
